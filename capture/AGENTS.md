# 天机阁开发约束

适用于 `capture/` 下的代码、前端、测试与文档。结合仓库根目录与用户当前指令执行。用户明确要求优先；本文件不授权新增范围、重启记录中的服务、删除数据或自动推送。


## 工作前必读

尚未阅读时，先读[开发规范](support/docs/开发规范.md)，再检查相关代码，开始修改。

按任务选读：

- UI／主题：[外观设置](support/docs/外观设置.md)
- 性能／资源回收：[性能优化](support/docs/性能优化.md)
- MCP：[MCP接入](support/docs/MCP接入.md)
- 模块职责：[架构与模块](support/docs/架构与模块_AI.md)

基本功能验证要求统一写在开发规范中。
完成后运行相关测试，更新[更新日志](support/docs/更新日志.md)。

当前会话已读且未变化的文档无需重复读取。

## 基本约束

- 先复现、再定位、最后修改；仅改本次需求涉及的模块，禁止顺带重写整个架构或换框架。
- 按用户指定顺序执行，每个功能完成验证后再进入下一项。功能差异清单不等于全部功能的实施授权。
- 抓包、存储、分析、重放分工不变；分析不能阻塞代理转发。不得把业务逻辑搬进前端或转发回调。
- 原始请求及正文保持可追溯，不覆盖；重复 Header/Query、顺序、原始编码、大整数与二进制不可悄悄丢失。未修改的数据不能因视图切换而重新序列化。
- 协议、截断、丢弃及错误状态必须如实显示。HTTP/2 开关不等于实际协商成功，更不等于保留原客户端指纹。
- UI 遵循现有黑白主题和控件；常用操作在外，低频操作进菜单。展开菜单不挤压布局，按钮区不加内容伸缩手柄。
- 类和主要方法写用途注释；不写仅复述代码的注释。依赖要在对应 requirements 中声明。
- 修复真实风险时增加针对性回归测试；界面要检查窄窗口与选中状态，协议改动要验证实际发送。测试不得使用真实业务 token 或向业务接口重放。
- 测试结果与未生效部分分别报告；源码完成、运行实例生效、已提交和已推送必须分开，不得混称“完成”。
- 不删除或移动 `.venv`、`data`、CA 私钥、研究样本及用户未提交文件。提交前检查状态与 diff，只包含授权文件。
- 同步 [更新日志](support/docs/更新日志.md) 和相关使用文档；以真实检查结果更新功能差异清单。

## 编写与修改代码的规则

- 修改前阅读相关实现，确认工作区已有改动、实际运行状态和本次验收标准；不根据截图猜测实现，不覆盖用户未提交的修改。
- 局部 UI 需求只调整对应 HTML、CSS 和必要的交互 JavaScript。不得顺带修改后端、代理、HTTPS 解密、Hook、存储或重放逻辑，不引入新框架和无必要依赖。
- 优先修改原有 CSS，合并同一组件的重复和冲突规则；不要在文件末尾不断追加覆盖。保留有必要的媒体查询、主题及组件作用域，避免通用选择器误伤其他区域。
- 保留现有 DOM ID、事件绑定、数据结构及全部功能。调整或移除控件时同步清理对应布局和事件逻辑；不得留下失效控件或重复事件绑定。
- 抓包与重放列表搜索工具栏保持单行，搜索框弹性伸缩并设置合理最大宽度；按钮不得重叠、换行挤压或溢出。窄窗口的表格使用内部横向滚动。
- 紧凑化通过减少内边距、间距和无效留白实现，不以缩小字体、复选框或整个列表可用区域代替。百分比优化先测量原尺寸，完成后报告真实尺寸和计算依据。
- 默认列宽仅用于未保存自定义宽度的列表；保留拖动、保存和恢复能力。地址列优先使用余量，默认方法列须完整显示 CONNECT；不得因打开/关闭详情反复压缩用户列宽。
- 保留搜索、筛选、排序、分页、重放、复制、内容折叠及合理的交互状态。菜单点击外部和 Escape 可关闭，菜单之间互斥，展开不推挤内容。
- 测试与改动风险匹配：行为或兼容性风险增加有意义的回归测试，不为纯样式写重复实现的测试。运行相关现有测试、语法检查与 `git diff --check`；失败先修根因。
- 基本功能、主题、窗口尺寸、动画及资源检查统一遵循[开发规范的验收要求](support/docs/开发规范.md#7-每次调整后的验收与资源检查)。
- 更新相关使用文档和更新日志，记录实际改动、验证结果与未验证部分。未获得用户明确授权，不自动提交或推送 Git；源码修改、实例生效、提交和推送分别报告。

## 6. 下拉按钮与菜单规范

- 区分两种组件：普通下拉由按钮整体点击展开菜单；分体下拉由主按钮执行操作、箭头按钮独立展开菜单。两者统一使用与“重放记录”一致的公共外观：连续外框、同高度、零间距、右侧箭头区域及中间细竖线；不混用点击逻辑。普通下拉即使视觉分区，整个触发器仍只展开菜单，不将标签区变为独立业务操作。
- 分体按钮必须是两个平级 button，外轮廓连续、同高度、零间距，中间一条细分隔线；箭头区域点击宽度至少 28px。主操作和箭头分别判断禁用状态。普通下拉可用单个 button 或原生 summary，内部标签与箭头使用非交互元素，不能嵌套 button；箭头视觉区域同样至少 28px，竖线不能只在悬停或展开时才出现。
- 箭头使用统一 SVG/CSS 图标，不使用不同字体的字符拼凑。展开时箭头方向变化，关闭时恢复；通过 aria-expanded 同步，不因选中、主题切换或禁用状态丢失。
- 菜单使用统一的间距、圆角、边框、阴影和层级。保持实色背景，避免底层按钮穿透显示或接收点击。隐藏菜单不得占据空间、接收点击或键盘焦点。
- 所有自定义菜单及筛选浮层统一通过 floating-panels.js 检测可视窗口边界，以触发按钮为锚点，展开不挤压页面。优先向下；空间不足时向上或向内调整，必要时缩小宽高并内部滚动，保留 8px 安全边距。滚动、窗口缩放和可视视口变化时重新定位，避免裁切、溢出或被父容器遮挡。原生 select 菜单保留系统边界处理。
- 点击外部、Escape、选择菜单项后关闭；菜单之间互斥。点击箭头只切换菜单，不执行主操作，也不触发父级操作。
- 支持键盘：Enter/Space 打开，方向键移动，Enter 确认，Escape 关闭并将焦点返回触发按钮。正确设置 aria-haspopup、aria-expanded 和菜单语义。
- 复用统一菜单控制器，集中管理当前展开菜单与关闭逻辑，避免每个业务菜单重复注册全局监听器。
- 验证所有下拉入口：主题、重放、重放记录、域名策略、更多及导出。覆盖各主题、窄窗口、边缘定位、独立禁用、箭头变化、外部关闭和键盘操作。
