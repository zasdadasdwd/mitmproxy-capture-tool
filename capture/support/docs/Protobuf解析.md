# Protobuf 只读解析

在请求详情的正文区域点击 **Protobuf 解析**，或在“完整查看”的正文显示方式选择 **Protobuf · 只读解码**。支持请求、原始请求及响应；读取已保存且完成 HTTP 内容解压的二进制正文，不使用可能损失二进制数据的 UTF-8 文本预览。

默认使用标准 Protocol Buffers wire 格式，展示字段编号、wire type 和数值。64 位整数用十进制字符串保留精度；重复字段按报文出现顺序展示。没有定义时无法确定字段名、signed/zigzag、浮点等声明类型；UTF-8 和嵌套消息只标为候选解释。

## 自定义定义

展开“自定义 Protobuf 定义（可选）”，粘贴定义或上传 `.proto`，点击“应用定义”后选择完整消息类型。应用定义后仍保持默认标准 wire 解码，选择类型后才按字段名解析。支持包名、嵌套消息、重复字段、packed 和 map；64 位数值保持字符串，bytes 使用 Base64。按定义查看时未声明的字段可能被跳过，请切回标准 wire 查看完整字段结构。

定义仅在当前页面内使用，不上传服务器、不写入请求。刷新页面后重新提供定义；“恢复标准解码”清除定义和类型选择。定义读取或校验失败会保留上一份有效定义。自定义定义模式暂不支持旧式 group（标准 wire 模式可展示）。当前不自动加载 import 文件；需要将依赖定义合并为一个自包含文件。

例如：

```proto
syntax = "proto3";
package example;
message Sample {
  uint64 id = 1;
  string name = 2;
}
```

选择 `example.Sample`，可将 `08 96 01 12 02 6f 6b` 解码为 `{"id":"150","name":"ok"}`。

## 限制与原文

- 正文解析上限 2 MiB，定义上限 256 KiB；设置字段数量和嵌套深度边界，避免阻塞页面。
- 标准候选展示每字段最多 4096 字节、共享 64 KiB 展示预算，截断处明确标记。解析视图的展示截断不会修改保存的原文。
- 未完整保存、正文截断、解压失败时拒绝作为完整 Protobuf 解码。gRPC 带独立帧封装，当前不直接解析为普通 Protobuf 消息。
- 解码失败可切回原始正文或下载已保存原文；复制按钮只复制当前展示结果。重放、编辑重放及下载始终使用原有数据链路。
- 字节读取按需进行，同一请求各分区有界缓存，关闭、切换请求或刷新时清理；迟到读取不能覆盖新请求。

前端自定义解析使用本地固定版本 protobuf.js，许可及来源见 `web/vendor/`。官方说明：[protobuf.js](https://github.com/protobufjs/protobuf.js)、[Protocol Buffers 编码](https://protobuf.dev/programming-guides/encoding/)。后端、MCP 工具契约及代理处理行为保持不变。
