# Capture 使用指南

Capture 是本机 mitmproxy 抓包工作台。管理页面默认在 `http://127.0.0.1:8765`，代理默认在 `127.0.0.1:8080`。管理服务启动后代理可以转发流量；点击“开始抓包”才会保存请求。

## 安装与启动

需要 Python 3.12 或更高版本。在项目根目录执行：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python main.py
```

然后在浏览器打开 `http://127.0.0.1:8765`。Windows 可把 `.venv/bin/python` 换成 `.venv\\Scripts\\python.exe`；目前采集通道使用 Unix socket，Windows 尚未验证。

`startup.toml` 设置 Web/MCP 端口、是否自动开始记录及第三方 Hook 模块。可以用 `.venv/bin/python main.py --config /完整路径/启动文件.toml` 指定另一份文件；修改进程配置后完整重启 main。每次 main 启动时，Web 与代理进程固定当时配置的 Hook 模块集合。运行期间修改 `startup.toml` 不会隐式增删模块；代理因端口或 Hook 顺序等设置重启时，仍使用该 main 进程启动时的模块集合。开始新抓包只会重建 Hook 实例，不重新发现模块。运行时不要编辑插件源码；源码修改需完整重启 main 才会在新进程中加载。常用代理初始值集中在根目录 `config.py` 的 `DEFAULT_SETTINGS` 字典，每项旁边有注释。首次运行从它生成设置；之后管理页面保存到 `data/settings.json`，启动时优先读取这份用户设置。改字典不会覆盖已有用户设置。

## 抓包流程

1. 在目标设备或应用中设置 HTTP/HTTPS 代理，填工作台显示的 IP 与端口。手机要与电脑在同一局域网，并在“设置 → 网络”把监听地址改为 `0.0.0.0`；手机不能使用电脑的 `127.0.0.1`。
2. 抓 HTTPS 时，先在“设置 → CA 证书管理”下载公开证书并按[证书安装说明](证书安装.md)信任。然后在 TLS 设置中选择全部解密或添加需要解密的域名。只想透传时可不安装证书。
3. 点击“开始抓包”，操作目标应用。请求会实时出现在列表；可按域名目录、快速筛选或“多条件筛选”缩小范围。多条件筛选的组可分别选 AND/OR，子组代表括号。
4. 点击请求看简要详情；再点击同一请求可收起。用“完整查看”读取完整报文，查看请求/响应头和正文；JSON 响应支持树形浏览。
5. 要验证参数，直接在该请求详情点击“重放”，或勾选多条请求后点击“重放选中”；结果进入独立重放记录。需要修改 URL、头或正文时，在重放右侧箭头选择“编辑后重放”。重放会向目标服务器重新发送请求。
6. 选择记录后可导出 cURL、Python/httpx、Python/requests、HAR、CSV 或 JSON。停止抓包只停止记录，代理仍可转发。每次重新开始会生成独立 SQLite 会话；历史数据在“设置 → 历史会话”中管理。

拒绝域名规则优先于 TLS 解密。外部代理或直连在“设置 → 网络”选择；修改监听端口、上游代理或 Hook 列表前先停止当前记录。

外层搜索可直接选择关键词范围。筛选面板有独立关键词；修改面板条件会清空外层关键词，改用面板条件查询。抓包与重放各自保存筛选，返回抓包时恢复原会话条件（当前页面内有效）。

记录数前的“清空当前请求”删除当前筛选匹配的请求及正文，包含其他页；无筛选时清空当前批次全部请求。筛选条件保留，无结果时禁用。删除不可恢复，执行前需确认；筛选结果一次最多 50000 条。筛选面板内的“重置全部筛选”只重置查询条件，不删除记录。

筛选与操作菜单点击外部会自动收起；打开其他操作菜单会关闭旧浮层。菜单内部可以正常输入、选择；按 Escape 优先收起浮层，正文与 JSON 树的折叠状态保持不变。

筛选面板的「关键词范围」可选择「请求正文」「响应正文」或「请求 / 响应正文」；「全部内容」也包含正文。多条件筛选中同样提供请求正文、响应正文的「包含 / 不包含」，可以放入 AND/OR 分组。正文查询忽略大小写，搜索已保存并解压后的内容，每条最多解压 16 MiB；建议同时限定域名或时间以减少扫描。缺失或不完整的正文未命中时，不算作明确“不包含”。查询结果是请求摘要，点击请求才读取详情。历史会话不需要迁移或重新抓包。

## 请求详情操作

侧栏操作栏为“完整查看 / 重放 ▾ / 域名策略 ▾ / ⋯”；窄面板缩短标签，保持单行。“⋯”包含 AI 分析、对比请求、cURL 与 requests 代码复制入口；完整查看内也使用重放分体按钮和更多菜单。菜单点击外部或按 Escape 收起，打开其他菜单关闭原菜单。

方法、URL、状态和原因集中展示；点击截断的 URL 可展开完整地址。请求 / 响应 / 原始 / 连接标签保留原分区数据和复制能力，原始请求不会被重新编码。CONNECT、阻止及无响应失败记录优先打开连接标签，其他报文仍可手动切换查看。

无内容的头部、正文默认折叠；有内容时展开。侧栏按内容自然滚动，长头部保留内部滚动上限；折叠选择及标签滚动位置在当前页面内记忆。侧栏宽度仍可拖动，不再显示侧栏数据区的上下伸缩手柄；完整查看的正文、Query 伸缩及格式化、JSON 树、SSE、下载功能继续保留。

## 导出 requests 脚本

勾选请求后，在导出格式中选择 **Python / requests**，下载 `capture.py`。脚本参照 `web_js` 的参数字典格式：`url` 单独一行，`headers` 逐项展开，UTF-8 正文写为原始字符串 `.encode()`，方便直接修改参数；二进制正文使用字节字面量。Query、JSON 和 URL 编码表单不会重新序列化，避免改变签名所依赖的原始内容。

单条脚本提供 `build_request_params()` 和 `send_request(params=None)`；批量脚本使用 `REQUESTS` 列表，并通过 `send_all()` 按导出顺序发送。导入脚本不会发送请求，直接运行脚本才会发送。执行前安装依赖：

```bash
python -m pip install requests
python capture.py
```

默认不指定代理、验证服务器证书、超时 30 秒且不自动跟随重定向；可在参数字典里修改 `proxies`、`verify`、`timeout` 和 `allow_redirects`。脚本使用普通 Python requests，不包含 curl_cffi 的 JA3 或 HTTP/2 参数。requests 导出会通过 HTTPHeaderDict 保留重复请求头；正文截断的请求不能导出为可运行代码。

## 查找参数来源

从请求详情选择一个参数片段后点击“分析”，或打开 `links.html`，选起点请求并输入参数名/值片段。全文搜索会查看请求 URL、原始请求与实际请求的头部/正文、响应头/正文，并展示出现时间线；较早响应中的相同值是来源候选，不等于已证明生成算法。图可旋转、缩放和点选节点。正在抓包时可以保持记录并实时追踪。详见[数据链路说明](数据链路.md)。

## 扩展自己的 Hook

最简方式是编辑根目录 `hook_template.py` 的 `TemplateHook`，保存后重启。做成独立模块时，新建可导入的 Python 模块，写：

```python
from capture.plugins import BaseHook


class MyTokenHook(BaseHook):
    """只处理指定域名的请求，默认不修改其他报文。"""

    name = "my_token_hook"
    description = "给示例 API 添加测试头"

    def on_request(self, flow, context):
        """请求发送前，可修改 URL、Header、Cookie、Query 或正文。"""
        if flow.request.host == "api.example.com":
            flow.request.headers["X-Debug"] = "1"

    def on_response(self, flow, context):
        """响应返回后，可修改状态、Header 或正文。"""
        pass
```

在 `startup.toml` 增加：

```toml
[extensions]
hook_modules = ["my_hooks"]
```

模块名是 Python 点分导入名，不是文件路径；模块需位于项目目录或安装在当前 `.venv`。完整重启 main 后到“设置 → 扩展”添加 `my_token_hook`、启用并调整顺序。Hook 方法必须是同步方法；模块会分别由 Web 与代理进程导入，不能依赖两进程共享的全局变量。导入失败时会回滚本次导入产生的 Hook 注册及相关模块导入缓存；这不撤销模块执行的任意外部副作用。默认空模板不会修改任何报文。

## Agent 与数据文件

Agent 可通过本机 MCP 查询请求与分析链路，见[MCP 接入说明](MCP接入.md)。查询记录可在管理页面查看。所有抓包会话分别保存在 `data/captures/<时间_ID>/`；`data/certificates/` 含 CA 私钥，不要把整个 `data/` 目录发给其他人。归档会话可在设置中下载 ZIP（含 SQLite 和正文文件）。运行中的数据库使用 WAL，不要只复制 `capture.sqlite` 一个文件。

遇到客户端“无网络”，先确认代理正在运行、客户端使用显示的真实局域网 IP/端口、两台设备可互通；HTTPS 问题再检查 CA 信任和 TLS 域名策略。管理页面只能在本机打开，不能用手机访问它来代替配置手机代理。

请求列表默认按开始时间倒序排列，最新请求在前。点击「请求时间」或「大小」表头可循环切换不排序、升序、降序；不排序恢复默认顺序。大小指保存记录中的响应正文大小，未获得大小的请求在显式排序时放在最后。排序覆盖全部筛选结果，翻页和实时刷新保留当前排序。

侧栏详情使用自然滚动和内容折叠；完整查看中的头部、正文、Query JSON 仍可通过底部横线拖动调整高度。详情和完整查看的「⋯」菜单提供 cURL 与 requests，选择后打开命令或 Python 代码文本框，由用户手动复制，不下载文件，无需勾选列表。requests 脚本将 URL 与 params 分开，重复 Query 与请求头使用列表保留；未编辑 Query 时保留原始 URL 编码，编辑 params 后按修改值发送。重复头通过准备请求后的 HTTPHeaderDict 发送，不合并成逗号字符串。

完整详情顶部的 URL 输入框预填当前完整请求地址，可修改域名、路径和 Query。修改会用于重放、编辑重放和 cURL/requests 代码生成，不会覆盖原始抓包记录；Query JSON 跟随输入同步解析，切换显示页签保留本次草稿，重新打开请求会恢复原始地址。

重放按来源协议选择传输：HTTP/2 请求启用 HTTP/2 协商，服务器不支持时回退 HTTP/1.1；HTTP/1 请求使用 HTTP/1.1。重放记录中的「发送请求」保存 httpx 实际构建的请求头和协商后的版本，「原始请求」保留重放前的快照。Host、Content-Length 会重新计算，重复请求头保留。当前重放不会保留原客户端 TLS/HTTP2 指纹，连接信息中的 replay_transport 会标记原始版本、是否改变版本及指纹保留状态，不能把业务参数一致理解为传输指纹一致。

### 编辑重放的参数表格

编辑方式可切换「原文」和「参数表格」。表格包含 Headers、Query、Body / JSON，支持添加、删除、↑ ↓ 调整顺序，重复名称按独立行保留。JSON 对象的值使用 JSON 原文，支持嵌套结构；数组、二进制及压缩正文使用原文编辑。未修改的 URL、正文编码和字节保持不变，切换视图不会重写。修改或排序可能导致签名失效，需要自行重新计算。Host、Content-Length 和连接专用头仍由重放传输层处理，不能保证完整网络报文逐字节一致。

### 连接信息

选择请求后打开「连接信息」，分别查看客户端 → 代理与代理 → 目标服务器两端的协议、已接受 ALPN、TLS 状态、密码套件和连接 ID。两端协议不同是可能的；ALPN 候选列表不能证明协商成功。相同连接 ID 表示同一个已记录连接，不代表请求互为参数来源。TCP/TLS 时长仅在引擎提供完整时间戳时显示。旧记录缺失字段显示未知，HTTPS URL 本身不能证明 TLS 版本或 HTTP/2。重放没有原客户端入站连接，查看下方的原协议和实际重放协议。

## 大正文与 SSE

设置的“抓包与存储”可设置常规内存缓存上限（默认 2 MiB）、流式正文保存开关和单个正文磁盘上限（默认 64 MiB）。设置影响之后的新请求，不补回旧会话已丢失的内容。

大正文、SSE、分块上传及无长度响应在转发时异步保存原始字节。共享排队缓存约 8 MiB，最多跟踪 128 个并行正文；磁盘慢、超限或写入失败不会等待磁盘再转发。停止记录会停止保存，已有连接仍继续传输。详情分别提示仍在接收、未缓存、截断、写入失败和中断，只有保存完整的请求才能用于完整重放。

流式转发不会把完整正文放回 mitmproxy 的 raw_content；需要完整正文的 request/response Hook 不适用于这些流，不能在流已转发后追溯修改。头部与连接扩展仍按现有引擎行为执行。

响应为 text/event-stream 时，简便详情默认按事件显示；完整详情可在 SSE 事件与原始正文间切换。仅显示以空行结束的完整事件，多行 data 合并，心跳和未结束尾部不计入。每次最多展示前 500 个事件，不是尾部滚动日志。

简便详情文本预览 64 KiB，完整详情文本及原始字节接口上限 16 MiB；“下载已保存原文”读取磁盘文件，不受展示上限限制。下载进行中的 SSE 时，只下载点击时已保存的前缀，并不代表连接结束。正文搜索仍受现有 16 MiB 扫描上限约束。压缩流无法完整解码时明确显示解码失败，gzip 可预览已接收部分。

源码更新后需重启工作台和代理引擎才能启用采集及下载后端；不会自动重启正在记录的实例。


## WebSocket 消息

新抓包的 WebSocket 握手请求会在简便和完整详情显示“WebSocket”标签。每页最多 100 条，按采集顺序展示客户端/服务端方向、时间、类型、原长度与截断状态。展开消息后显示文本或二进制十六进制，可复制内容；实时更新保留当前分页。

默认每连接保存前 1000 条消息、正文累计 4 MiB，单条最多 64 KiB。这两个连接上限可在根目录配置的默认对象中设置 websocket_message_limit、websocket_body_limit。超过配额、采集队列丢弃或正文被截断会明确提示，不影响网络转发。这里的保存量上限不等于 mitmproxy 自身的消息缓冲上限。

查看的是 mitmproxy 重组并解压后的 TEXT/BINARY 消息，不是逐个原始分片或 PING/PONG/CLOSE 控制帧。结束事件保留可获得的关闭码与原因；停止记录后的未关闭会话显示中断。旧会话不能补回此前未采集的消息，目前不支持 WebSocket 消息发送或重放，HTTP 重放会明确拒绝这类请求。

删除握手请求会一并清除消息记录，后续长连接事件不会重新创建已删除请求。旧 SQLite 无需手工迁移，首次收到消息时增加独立消息表。需重启工作台及代理引擎后，新抓包才能启用此功能。

## 请求差异对比

- 同一会话勾选两条请求，在“更多”菜单选择“对比选中（2 条）”。A 为先勾选的基准，B 为后勾选的目标；窗口可交换 A/B。
- 简便和完整详情的“对比”菜单可“设为对比基准”，然后切换请求或会话，选择“与基准对比”。基准仅保留在当前页面内，刷新后清空；不修改抓包数据。
- 重放记录可在同一菜单选择“与重放来源对比”。来源已删除时会明确报错，不执行重放。

窗口按概览、请求头、Query、请求体、响应头、响应体及原始请求分区；区分新增、删除、修改和字段不存在。原始头顺序、Query 顺序及百分号编码单独比较；JSON 大整数在后端比较，不经过前端浮点转换。单个差异值最多显示 512 字符，总差异最多展示前 100 项，限制会明确提示。

正文使用已保存的 64 KiB 文本预览；原始字节仅比较前 64 KiB 的 SHA256 与保存长度，可识别二进制/压缩编码前缀的变化。大正文后半部分、尚未接收或未保存的数据不参与比较，即使没有差异也不能据此宣称完整正文相同。WebSocket 消息不在本次 HTTP 请求对比范围内。

旧后端可使用已有对比接口，窗口会提示原始顺序、协议等新检查需要重启后端才生效。对比不会停止抓包，也不会向业务服务器发送请求。


## 抓包期间删除记录

“更多”中的“删除选中”和“清空当前记录”可在抓包、重放中使用，仍需确认且不可恢复。清空覆盖当前会话已入库记录，包括筛选隐藏的记录；新请求继续保存，已删除记录的迟到响应不会恢复记录。“删除当前批次”会移除会话目录，必须先停止该会话。后端需要重启后才能启用记录中删除。

读取相同请求会合并等待，切换筛选或详情会取消过时读取；网络及正文传输超过 20 秒会显示超时，可缩小正文搜索范围后重试。首次 API 失败不会关闭实时恢复连接。上述超时不用于重放、删除等写操作，避免误报写操作未执行。

### 列表显示密度

抓包和重放列表采用紧凑行高，搜索工具栏保持单行，关键词框随可用宽度收缩。默认地址列优先占用余量，窄窗口可横向滚动；CONNECT 方法保留完整显示。列宽仍可拖动，已保存的宽度不会被新默认比例覆盖。详情头部表格同步压缩内边距，复制、折叠和滚动功能保持原样。

### 合并重放记录与定位

点击顶部「重放记录」直接显示本次启动所有重放批次的请求，数字气泡统计请求总数，不占按钮正文宽度。未选中请求时显示全部；选中抓包请求后进入，会定位其最新重放记录并打开响应详情；选中重放请求后进入，会定位原记录。定位只调整页码和滚动位置，不缩小列表范围。没有匹配的重放时仍显示全部记录并提示。

入口旁的箭头用于管理批次；选择批次会在合并列表定位该批次的最新请求。合并列表的筛选、排序和分页作用于全部重放记录，返回抓包保留抓包原筛选。跨批次勾选后的重放、删除和文件导出按真实批次分别执行，文件导出可能生成多个带批次名的文件。单条详情、编辑重放、复制代码和对比使用对应请求的实际批次。聚合查询深页 offset 上限为 100000，超过时提示缩小范围。

本次新增了后端只读聚合接口。旧运行实例需要在停止抓包后重启工作台；仅刷新前端不足以加载新增接口。
