# 抓包证书安装

此工具默认管理地址为 `http://127.0.0.1:8765`，代理端口为 `8080`。
TLS 透传不需要安装证书；查看 HTTPS 请求和响应内容需要安装并信任本工具的 CA。

## 1. 启动并设置代理

1. 打开管理界面，代理会自动开始转发，首次启动会生成 CA。点击“开始抓包”才保存请求；下载证书不需要开启抓包。
2. 本机客户端的 HTTP 和 HTTPS 代理均设置为 `127.0.0.1:8080`。
3. 手机或另一台电脑：先停止抓包，在“设置”中将监听地址改为 `0.0.0.0`，再启动。
4. 手机和电脑连接同一个可互通的局域网，代理服务器填写界面顶部显示的电脑局域网 IP 和当前端口（默认 `8080`）。`0.0.0.0` 是监听地址，不能作为手机代理服务器地址。
5. 如无法连接，检查防火墙是否允许该代理端口，以及 Wi-Fi 是否启用了客户端隔离。

管理界面只在本机开放。不要把代理端口映射到公网。

## 2. 下载证书

设置好代理后，在客户端浏览器打开 **http://mitm.it**，选择对应系统下载证书。
本机也可以使用管理界面左下角“设置 → CA 证书管理 → 下载证书”。不同电脑运行的工具拥有不同 CA，必须安装你正在连接的那个实例的证书。

证书保存在 `data/certificates/`，不会随抓包会话重新生成。只分享 `mitmproxy-ca-cert.*` 公开证书文件，不要分享 `mitmproxy-ca.pem`，该文件包含私钥。

## 3. 安装并信任

### Windows

打开证书安装向导，选择“当前用户”，手动选择“受信任的根证书颁发机构”，完成安装。部分浏览器有自己的证书管理设置，需要另外导入。

### macOS

在本机浏览器进入“设置 → CA 证书”，点击“安装并信任”。工具会核对当前 CA 指纹和有效期，转换成 macOS 可识别的 DER 证书，安装到登录钥匙串，并为当前用户设置 SSL 信任。系统可能弹出授权窗口，请按提示确认；取消授权会显示失败信息，可以重试。此操作不需要桌面 App，也不会修改系统代理。

安装作用于运行 Python 管理服务的 Mac。Python、Firefox 等使用独立证书库的客户端仍需单独配置。无需继续使用时，在钥匙串访问中删除对应指纹的 mitmproxy CA。

也可以手动安装：

使用“钥匙串访问”导入证书到登录或系统钥匙串。找到 mitmproxy 证书，双击打开“信任”，将 SSL 信任设置为“始终信任”，按系统提示确认。

### iPhone / iPad

1. 在 Safari 通过 `http://mitm.it` 下载 iOS 证书描述文件。
2. 到“设置 → 通用 → VPN 与设备管理”安装该描述文件。
3. 到“设置 → 通用 → 关于本机 → 证书信任设置”，开启该根证书的完全信任。

只安装描述文件而没有开启完全信任，HTTPS 仍可能失败。菜单名称随系统版本略有不同。

### Android

在设置中搜索“安装证书”，选择 CA 证书并按系统提示安装。不同厂商的入口和支持格式可能不同，可从 `http://mitm.it` 获取 Android 对应证书。

许多 Android 应用不会信任用户安装的 CA。测试自己开发的应用时，需要在其调试构建的 Network Security Configuration 中允许用户 CA。应用证书固定也可能使抓包失败；安装 CA 本身不会解决固定校验。

### Python 客户端

Python 库可能不使用系统证书库。以 httpx 为例，显式指定代理和本工具公开 CA：

```python
import ssl
import httpx

context = ssl.create_default_context(cafile="data/certificates/mitmproxy-ca-cert.pem")
with httpx.Client(proxy="http://127.0.0.1:8080", verify=context) as client:
    response = client.get("https://example.com")
    print(response.status_code)
```

## 4. 验证解密

1. 在“设置”中选择“仅列表解密”，加入目标域名，如 `example.com`，保存。
2. 关闭旧连接或重启测试客户端，再访问该域名。
3. 如果列表出现 HTTPS 请求并能看到 Headers 和正文，说明解密成功。
4. `*.example.com` 只匹配子域名，根域名 `example.com` 要单独添加。

未命中解密列表的连接显示“透传”，只能查看连接摘要。拒绝规则优先于 TLS 设置。

## 5. 常见问题

- **页面报证书错误**：确认安装的是当前工具实例的 CA，并已完成信任；检查 TLS 解密列表和连接错误详情。
- **浏览器正常，App 失败**：可能是不信任用户 CA 或有证书固定。先将该域名透传，确认原连接正常，再检查应用调试配置。
- **没有请求**：检查代理地址、端口和客户端是否真正使用代理；部分客户端会绕过本地地址。
- **修改配置后没变化**：TLS 模式在新连接生效，需要重新建立连接。
- **看不到完整正文**：大响应和 SSE 采用流式转发，超限正文会明确标记为未采集或截断。

## 6. 停止使用

“停止抓包”仅停止记录，代理仍继续转发；要退出工具，先关闭客户端的手动代理，再退出管理服务。无需继续使用 CA 时，从系统证书管理器或 iOS 描述文件中移除本工具的证书和信任。

参考：[mitmproxy 证书文档](https://docs.mitmproxy.org/stable/concepts/certificates/)、[Android 网络安全配置](https://developer.android.com/privacy-and-security/security-config)。
