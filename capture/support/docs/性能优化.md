# 性能优化与资源回收验证

## 2026-10-26 · 动态背景与闲置资源

此前在用户环境观察到 WebKit 物理 footprint 约 1.7 GiB，图片/图形区域占主要部分；后端约 62 MiB。内置背景为 1280×720、150 帧 WebP，仅所有帧 RGBA 理论大小就约 527 MiB。此证据指向原生完整动画的缓存压力，不证明所有卡顿均由背景引起。本次没有发现运行中的工作台监听，未采到当前卡顿调用栈。

GIF/WebP 改成压缩帧索引与逐帧静态解码，在单个源尺寸 Canvas 上合成；最多一个解码在途，迟到结果关闭不绘制，快速切换只保留最后任务。每帧 ImageBitmap 使用后关闭，暂停、隐藏、透明度为零、替换和关闭释放画布、帧索引及 GIF 恢复区域。没有预解码并保留全片，也没有增加依赖或缩改用户原图。浏览器不支持时回退真实静态首帧并提示。

桌面窗口额外传递最小化/恢复状态，避免只依赖 `document.hidden`。新页面加载前不调用 JS，加载后重新发布窗口状态；恢复遵循播放开关。新增桥接需要下次启动 App 生效，不会自动重启现有抓包。

实际 Cocoa 独立窗口，临时浏览器存储、同一内置素材，`vmmap` 每 5 秒采样：

| 场景 | WebKit footprint |
| --- | ---: |
| 前台连续播放 120 秒，24 次样本 | 95.4–130.1 MiB |
| 独立生命周期轮次：连续播放 5 秒 | 100.2 MiB |
| 该轮再做 12 次暂停/恢复 | 190.0 MiB |
| 该轮替换合成 GIF、关闭背景后约 2 秒 | 64.6 MiB |

GIF 使用两帧红绿合成文件，实际 Canvas 像素确认两种颜色；桥接暂停后画布为零、恢复回到 1280px。当前测试会话调用系统最小化没有生效，因此最小化/恢复通过生产 PyWebView 事件模拟验证，**不声称真实 Dock 最小化已验证**。初轮 120 秒播放完成后在系统最小化阶段失败，原始数据保留；随后生命周期单独通过，未把失败整轮写成通过。

生命周期轮次 rAF P95 18ms、最大 771ms、1 次超过 50ms，包含 `vmmap` 暂停及窗口状态切换的干扰，不代表源动画帧率或无卡顿。本次只是短时连续播放、切换和释放检查，未进行数小时闲置复现、所有 GIF disposal/色彩配置的原生逐像素对照或跨设备 GPU 测量；浏览器缓存回收时机由系统管理，不保证关闭后立即回到基线。

224 项 Python 和 131 项前端回归通过（保留既有 Starlette/httpx 弃用警告）。完整工作台在内置背景播放下通过搜索、筛选、清空、普通/透传/阻止/错误详情、模拟重放与返回、菜单、五套主题及 1280/900/600px 检查，无页面脚本错误。所用 API 为合成数据服务，未连接实际业务接口。

原始结果：[background-memory-20261026.json](benchmarks/background-memory-20261026.json)。复现（macOS，已安装桌面依赖，会打开独立窗口）：

```sh
PYTHONPATH=. .venv/bin/python capture/support/scripts/benchmark_background_memory.py --seconds 120 --output /tmp/tianji-background-memory.json
```


## 2026-10-09 · UI 动画、连续操作与回归复测

使用 macOS 的 Codex 内置浏览器及独立本机合成服务，不连接真实业务接口、不重启记录服务。临时测量脚本统计最近 10 秒的 requestAnimationFrame 帧间隔、主线程长任务、对象 URL 数量及 performance.memory；脚本不进入生产页面。主窗口 1280×800，另检查 900×600、600×450 与 600×650 的深浅主题和浮层边界。

| 场景（每个窗口约 600 个采样） | 帧间隔 P95 | 最大间隔 | 超过 50 ms 的间隔 |
| --- | ---: | ---: | ---: |
| 5 条请求，无动画 | 17.6 ms | 17.8 ms | 0 |
| 内置动画播放 | 16.8 ms | 17.8 ms | 0 |
| 播放下完成 30 轮详情切换和域名菜单操作 | 17.6 ms | 17.8 ms | 0 |
| 暂停动画 | 17.6 ms | 17.7 ms | 0 |
| 5000 条合成数据，每页 200 行，无动画滚动 | 16.8 ms | 17.7 ms | 0 |
| 每页 200 行，动画播放下滚动及翻页 | 17.6 ms | 17.8 ms | 0 |

记录中没有主线程长任务。无动画与播放模式各做 5 轮上下滚动，播放模式另做 5 轮前后翻页。帧间隔中位数约 16.7 ms；这只是本机短时 rAF 指标，不等同于动图源帧率、实际呈现帧率或所有设备均无卡顿，也不据单轮微小差异声称动画能提升性能。

连续操作约 280 秒：20 轮播放/暂停后保留 1 个静态 URL；PNG/GIF 替换共尝试 12 次，其中后 6 次逐项等待保存成功，覆盖快速替换取消与正常替换。移除背景后创建的 41 个 URL 全部撤销，活动 URL 为 0；追加 50 轮菜单操作后仍为 0。相同详情状态的 DOM 节点数为 863，没有随菜单操作持续增长。JS 堆在移除后约 19.4 MB，追加操作后回落至约 17.3 MB；未强制 GC，短时样本没有持续单向增长，不能据此排除长期泄漏或解码/GPU 内存增长。

本次修复两项必要交互问题：共享浮层直接读取展开状态，避免定位 RAF 前按 Escape 错误关闭详情；菜单补齐方向键、Home/End 导航，跳过隐藏及禁用项，筛选输入保留原生按键行为。主题菜单继续使用原有导航逻辑，无代理、存储、筛选或重放业务变更。

功能验证覆盖搜索有/无匹配、CONNECT 方法筛选、五种状态过滤、独立清空、抓包/重放切换、普通/CONNECT/阻止/错误/空内容详情、直接重放的本机模拟调用和编辑弹窗，以及菜单关闭、焦点与窄窗口定位。过滤和重放服务为合成响应；真实过滤与重放逻辑由相关现有测试覆盖，未向外部网站发送重放。

限制：测试浏览器隐藏界面和切换标签后仍报告 document.hidden=false，因此真实页面隐藏恢复没有验证通过，仍由模拟生命周期测试覆盖；系统减少动态效果同样仅模拟验证。未测量 GPU/解码内存、进程 RSS、长期真实流量或打包的 PyWebView。源码测试通过不代表用户当前实例已全部生效。

201 项 Python 测试、96 项前端测试、相关 JS 语法和 diff 检查通过。存在一项现有 Starlette/httpx 弃用警告，未新增依赖。5 万条数据库基准复测：首次目录 141.744 ms、排序中位数 3.310 ms、第一页 3.599 ms；100 次正文替换后 2 个文件、删除后 1 个基准文件、关闭后数据库连接 0，与此前优化结果接近，不另作无证据的性能改写。

原始记录：[UI 测量](benchmarks/ui-performance-20261009.json)、[数据库复测](benchmarks/performance-20261009-verification.json)。未提交或推送。

## 2026-10-09 · 首次目录加载、排序与失败回收

同一台 macOS、Python 3.12 的临时 SQLite，5 万条合成请求、20 个路径、不同 Query，以及一个 8 MiB 响应。对修改前的 HEAD 存储实现和本次实现各运行三轮；每项 12 次，正文替换 100 次，下表为三轮统计值的中位数。计时开启 tracemalloc，包含其开销，不代表 HTTP 接口延迟、进程 RSS、WebKit 渲染或网络吞吐。

| 项目 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 首次目录加载 | 763.920 ms | 138.831 ms |
| 显式时间倒序列表 | 50.561 ms | 3.297 ms |
| 默认第一页 | 3.201 ms | 3.389 ms |
| 第 40,001 条开始的分页 | 4.629 ms | 4.599 ms |
| GET + 200 筛选 | 46.732 ms | 45.663 ms |
| 8 MiB 正文预览 | 0.332 ms | 0.327 ms |
| 正文替换写入 | 0.904 ms | 0.863 ms |

首次目录约减少 82%，显式时间倒序约减少 93%。目录解析剔除不使用的 Query/Fragment，复用有界 URL 解析缓存，并逐行归并，避免按完整 URL 建临时排序表。时间倒序直接使用现有索引，保留 NULL 最后、同时间 ID 顺序以及先排序后分页。默认页、深分页、正文预览变化较小；不声称它们都有提升。大量匹配的组合筛选仍约 46 ms，尚未进行新的索引迁移。

资源回收机制：

- 正文保存跟踪本次创建文件及事务提交边界；磁盘部分写入、后续解码或序列化失败时，仅回收未提交半成品。旧记录及外部流式写入器提供的正文保留。
- 100 次替换后只保留 1 个替换正文，加上基准的 8 MiB 正文共 2 个文件；删除替换请求后只剩基准正文，Store 关闭后连接数为 0。既有请求删除标记继续防止迟到事件复活。
- 代理初始化的 socket、控制文件、日志均纳入异常清理范围，取消启动同样关闭资源并重新抛出取消。测试使用 mock，不启动代理。
- 故障日志只读末尾 2000 字节，避免大日志全量读入内存；测试跟踪底层 read 参数，验证实际读取有界。

不强制调用 Python 全局 GC，不周期性扫描或删除用户抓包、证书和分析结果。运行中的代理日志、持久分析结果仍可能增长；本次未引入保留天数或自动删除策略，也未验证长时间真实流量、动画背景 CPU/GPU 或整页卡顿。

201 项 Python 测试、83 项前端测试，以及 ruff 和 diff 检查通过。Python 测试有一项现有 Starlette/httpx 弃用警告；本次没有升级依赖。

原始三轮记录及环境信息：[performance-20261009.json](benchmarks/performance-20261009.json)，修改前基准为 `bbb25ec` 的存储实现。复现最新实现：

```sh
.venv/bin/python -m capture.support.scripts.benchmark_workbench --output /tmp/tianji-performance.json
.venv/bin/python -m pytest -q capture/support/tests
node --test capture/support/tests/web/*.test.cjs
```

本次后端修改在下次重启工作台时生效；未中断当前抓包，未提交或推送。

## 2026-10-01 · 缓存与正文预览

使用临时 SQLite 构造 5 万条请求（同一域名、20 个路径、不同查询参数）及一个 8 MiB 未压缩响应。没有修改真实抓包数据。每项测量 12 次，中位数统计；内存使用 tracemalloc，统计 Python 分配峰值。结果只代表本机该数据分布，不代表网络转发吞吐。

| 项目 | 优化前 | 优化后 |
| --- | --- | --- |
| 目录查询中位数 | 684.788 ms | 0.220 ms |
| 8 MiB 响应预览中位数 | 1.400 ms | 0.333 ms |
| 预览 Python 分配峰值 | 8388.9 KiB | 262.8 KiB |
| 完整查看 JSON 大小（原始模式 / 文本模式） | 30,758,402 字节 | 8,388,743 字节 |

目录首次加载仍需遍历数据库，本次约 720 ms；改善的是高频的后续刷新。新增请求和 URL 修改增量维护计数，响应生命周期更新不会重复计数。删除请求会使目录缓存失效后重建；最多保留 8 个会话的目录缓存，随 SQLite 连接淘汰。

未压缩预览只从文件读 64 KiB 加一个字节，保留截断判断。压缩正文仍按原有有界解压处理，这次没有声称降低其完整压缩输入的读取内存。完整查看仅省去展示用不到的原始/解码 Base64；默认 API、编辑、重放和导出继续读取原始字节。

MCP 实时日志使用服务共享快照，文件未变时不重新解析；多个订阅者共享解析结果，隐藏页面停止订阅。日志滚动与追加会自动使缓存失效。

回归覆盖目录计数、URL 修改、删除、并发写入、压缩正文、截断、原始字节保持、日志追加与共享缓存；共 64 项测试通过。

```sh
.venv/bin/python -m pytest -q
```
