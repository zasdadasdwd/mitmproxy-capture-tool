# 天机阁开发规范

本规范约束后续 Agent 和人工开发，目标是可扩展、易理解、可验证。适用于根目录 `main.py`、`app_main.py`、`mcp_server.py`、`config.py`、`hook_template.py` 及 `capture/`。以用户当前明确指令为最高任务依据；已有仓库指令仍需遵守。

## Agent 规范

1. 开始前确认当前需求、修改范围、运行状态和 Git 工作区，阅读相关模块而不是猜实现。
2. 用户要求按顺序时逐项完成；提出建议或记录功能差异不代表得到实施全部建议的授权。
3. 在当前模块中做最小完整修改。没有明确需求，不更换框架、不批量改名、不整理无关目录、不重写其他模块。
4. 用户已有修改必须保留。禁止为“清理”而 reset、删除抓包数据、CA、样本或虚拟环境；不要把私有数据纳入提交。
5. 正在记录的进程不得自行重启。本地静态资源可以刷新；后端变更要说明需要重启，确认实际记录状态后处理。
6. 有证据再下结论。区分引擎能力、当前工具能力、已测试能力、推测；不要承诺指纹一致、参数因果关系或全平台可用。
7. 不自动推送、发布、改系统代理或安装证书，除非用户已经授权相应动作。完成必要准备与验证，不反复请求已有授权。
8. 用合成数据和本机测试服务；不向实际业务服务发送测试请求，不在日志、文档和截图中暴露 token、Cookie 或私钥。
9. 不必为每个样式写测试；有真实回归风险时写行为测试。测试失败先修根因，不能删除断言掩盖失败。
10. 交付说明只列实际改动、验证、限制与是否已生效；不把未运行的测试写成通过，不把未发布的代码写成正式版本。

## UI 规范

- 保持原生 HTML/CSS/JavaScript、现有黑白主题、色彩变量与控件风格。功能开发不顺带更换品牌、设置布局或整个导航。
- 抓包列表常用筛选、多条件筛选、重放留在外部；低频操作用菜单，菜单不能变成一串始终展开的按钮。
- 工具栏高度由内容自然确定，按钮不被伸缩拖动压扁；菜单/策略浮层不参与正文布局，不能推挤 URL、标签和报文内容。
- 仅内容区域提供伸缩与折叠。关闭按钮固定在所属弹窗/面板右上角，不能随正文滚动失去入口。
- 选中、展开、禁用、加载状态与实际状态一致；同步 `aria-pressed`、`aria-expanded` 等语义，能用键盘操作。
- 小窗口允许合理换行和内部滚动，避免整页横向溢出。检查约 1280、900、600 像素宽度及黑白主题。
- 保留用户拖动宽度、展开状态和编辑草稿；打开/关闭详情后列表恢复可用宽度，不能累计缩小列宽。
- 表格允许重复键和排序，JSON 展示不能改变数值精度。原文与解析模式切换不能直接重写原始正文。
- 错误在对应区域明确显示，不能静默清空内容或显示旧请求。异步响应不得覆盖用户已切换的请求或会话。
- 手动复制代码框和真实文件导出必须区分；名称、按钮行为与用户预期一致。

## 功能规范

- 每次抓包独立会话；历史数据只读查询与当前采集隔离。停止记录后代理继续转发，除非用户明确停止代理。
- 原始请求、Hook 后请求、响应和重放记录分开保存。重放产生新记录，不覆盖来源，不默认再次执行 Hook。
- 原始正文使用字节保存，显示解码属于视图。截断、流式未缓存、读取失败、空正文要分开处理，不能把缺失数据伪装成空值。
- Headers 与 Query 用有序键值对处理。表单和 JSON 表格仅修改被编辑字段；重复键、字段顺序、百分号编码及 JSON 大整数不得被无意规范化。
- 原文重放保留可保留的业务数据，不承诺完整网络报文逐字节相同；Host、长度、连接专用头、HTTP/2 伪头等可能由传输层处理。
- 重放根据来源协议选择：HTTP/2 允许协商与回退，HTTP/1 使用 HTTP/1.1。记录真实结果；不支持的协议/正文操作要明确提示。
- TLS 指纹、HTTP/2 指纹和业务参数一致性分别对待，禁止用改版本字段假装协议或指纹保留。
- 查询应用在全会话数据再分页，排序同样先排序再分页。AND/OR 优先级必须用组表达，不能暗含用户不知的优先级。
- 链路搜索跨请求头、请求体、响应头、响应体及 URL，按选定范围工作；起始请求只是参照。包含匹配和时序只是证据，不证明因果关系。
- 有界队列、正文上限、分页、取消和超时必须保留；分析计算不能占用代理转发事件循环执行重任务。
- CA 私钥、抓包 SQLite 与正文不上传仓库；错误日志和 MCP 日志不能自动记录整份敏感正文。
- 向第三方扩展提供稳定 BaseHook 注册接口、上下文和注释，不能让新功能要求改内部引擎才能使用。

## 代码规范

- 按现有边界组织：`engine` 转发和 Hook；`backend/api` HTTP 适配；`backend` 服务与存储；`analysis/links` 分析；`agent_mcp` Agent 接口；`web` 展示；`desktop` 启动外壳；`support` 测试文档脚本。
- 有状态、生命周期或可替换接口时用类；纯转换用函数，不为“架构”堆空类与层级。
- 类、公共接口和主要方法说明用途、关键约束与必要副作用。复杂的保留编码/并发处理说明原因。
- 参数验证靠明确类型和边界校验。错误不得静默吞掉；保持原异常因果。资源用上下文管理或 finally 清理。
- 阻塞数据库与文件 I/O 不放在 FastAPI 事件循环或转发 Hook 中；使用已有线程/进程隔离和事务约束。
- 禁止拼接 SQL 字段或执行任意表达式；可排序字段、格式、URL 协议等使用白名单。
- MCP 工具按真实副作用设置注解，输出和分页有界；工具契约变化同步配套 Skill、指南资源和接入文档，验证协议发现与调用。Skill 不得虚构未实现能力或扩大用户授权。
- 前端展示用户输入用 `textContent` 或控件值，避免直接拼接 HTML。事件绑定和状态所有权集中，禁止重复绑定。
- CSS 优先改原有规则；临时覆盖必须说明原因，防止不断追加互相冲突的规则。样式无关时不全文件格式化。
- 依赖选择稳定、必要、可解释；不要为一个菜单或简单表格引入大型前端框架。
- 保持入口和配置兼容，不要求虚拟环境固定名字；常用默认值放在带注释的配置对象。
- Git 提交内容只涉及当前授权工作；使用中文描述具体修改，不把会话经过写入提交说明。

## 验证与交付门槛

```bash
# 从项目根目录运行，解释器路径可替换为自己的环境。
.venv/bin/python -m pytest -q capture/support/tests
.venv/bin/ruff check <本次改动的Python文件>
node --test capture/support/tests/web/*.test.cjs
node --check capture/web/app.js
git diff --check
```

界面改动检查实际浏览器/桌面外壳交互。协议变动至少用本机服务器检查真实版本与报文，包含回退、重复字段和失败状态。验证通过后，更新日志写“本次源码变更”；需要重启、未部署或未推送的部分单独注明。
